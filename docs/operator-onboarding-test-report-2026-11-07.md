# 运营商配置化接入验收报告

日期：2026-11-07。环境：本地 Windows、Java 8、Docker、MySQL 8.0.36，应用单实例，已有 Redis / RocketMQ / Nacos 与模拟桩服务。不是生产容量测试，也不是厂商协议或真实设备验收。

## 已实现

- 平台管理员开户：在一个本地事务内初始化运营商、部门、岗位、角色、管理员、关系及默认规则，显式设置初始密码。
- 运营商独立规则：最长充电时长、会员白名单、版本冲突控制；不同端口共享读取，修改配置或名单时排他锁定同一规则。
- 会员注册与余额账户归属、设备站点/桩/端口归属校验；后台身份取自服务端登录态。
- 后台设备、会员、订单以及工单/告警隔离；会员个人资料与余额等查询绑定有效 token。
- 模拟器按已存储的设备归属执行持久化操作；停用/到期禁止新入口，已在充电的订单仍能安全停止并结算。

## 修复过程

1. 有效运营商被误判到期：驱动返回的 DATETIME 不满足原 Java Date 类型判断；改为数据库时间比较，真实驱动回归通过。
2. 新运营商模拟设备启动失败：模拟器 ORM 沿用默认 9999；改为设备实际归属作用域。
3. 端口后台详情与会员内部接口边界不足：区分后台归属校验与内部服务调用，保留会员正常启停链路。
4. 公开会员查询代理绕过内部认证：会员 token 派生身份，客户端参数必须与登录会员一致。
5. 运营商看不到本租户会员订单：移除后台账号 ID 对会员订单的错误过滤，启用租户分页过滤，后台订单编号详情增加租户校验。
6. system 镜像重建仍运行旧 JAR：应用目录匿名卷遮蔽镜像文件；移除 Dockerfile 的该卷声明，旧匿名卷不删除。

## 实施决策与限制

- 在已有非主分支继续，保留其他脏文件；代价是没有单独 worktree，采用精确路径提交隔离改动。
- Windows 下直接维护实施记录；代价是手工记录步骤和命令。
- 旧随机密码/邮件开户 API 返回改用新入口；代价是旧 API 客户端需迁移至 `/tenant/onboard`。
- 模拟器持久化按设备归属执行；代价是缺失/已删除设备不能作为任意演示对象启动。
- 旧微信登录分支补上生命周期和余额归属检查；未配置真实微信凭据，不能声称微信授权或短信已完成联调。
- 未新增硬件协议、厂商 SPI 或运营商外部系统对接；本期交付是现有 SaaS 内的账号、权限、设备及充电规则配置化接入。
- 保持当前功能分支和本地部署，未发布 GitHub/Pages，未编辑简历或面试助手。历史量化不充当本次测试结果。
